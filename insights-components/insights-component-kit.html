Insights Component Kit

Styled with the Ovie design system (DESIGN.md): Figtree, plum brand, flat white cards, 12px radius, sentence case. Red, orange and green are semantic only (not covered or expired, needs attention, covered). Turquoise and yellow are the neutral accents for charts and counts. Text keeps the accessible semantic colors. The commercial auto extraction for Gallatin County Water District (CPO-0632562-02), split into 8 chunks of data that belong together. Each chunk has 2–3 component options, drawn here with the real values. The LLM returns one block per chunk with a component name and the chunk's data; the front end looks up the name and renders it. Nothing about the layout depends on the policy type.

One schema per chunkAll options in a chunk read the same data. Switching from option A to C is a front-end change, not a new extraction.
Everything visibleValues, qualifiers, who it applies to and a plain sentence show by default. Taps are only for the source page and Ask Ovie.
Visual + the numbersEvery visual sits next to the actual values, so nobody has to read a chart to get an amount.
Not found ≠ not coveredMissing data goes to the Gaps chunk, never into Exclusions or a ✕.

For the LLM dev

How the extraction plugs in

The LLM returns one JSON object with an ordered list of blocks. The front end has one renderer per component name and a fallback. Values are typed, never pre-formatted strings like "$1,000,000 per accident", so the UI can format currency, draw bars and compare amounts.

Block envelope{ chunk, component, title?, data, sources[] }. component must be a name registered for that chunk.
FallbackUnknown or invalid component → front end renders generic.kv_list from the same data. Nothing is dropped.
No citation, no renderEvery item carries sources (doc + page/section). Uncited items go to Gaps.
One fact, one placeThe same concept (e.g. hired-auto cap) appears once as a fact and once at most as a watch point, linked by relatedIds.
Prompt snippet for the extraction
Return JSON: { "policyType": "...", "jurisdiction": "...", "blocks": [ ... ] }.
Emit blocks in this order when data exists: header, premium, coverage, subjects, exclusion, watch, deductible, evidence.
For each block set "component" to one of:
  header      → policy_header.summary_card | policy_header.timeline_list | policy_header.id_card
  premium     → premium.breakdown_bar | premium.receipt | premium.waffle
  coverage    → coverage.limit_rows | coverage.limit_bars | coverage.matrix
  subjects    → subjects.value_bars | subjects.table | subjects.age_axis
  exclusion   → exclusion.icon_list | exclusion.tile_grid | exclusion.grouped
  watch       → watch.severity_cards | watch.stripe_rows | watch.action_cards
  deductible  → deductible.rows | deductible.ladder | deductible.scale
  evidence    → evidence.gap_list | evidence.page_strip | evidence.found_missing
Default to the first option in each line unless told otherwise.
Rules:
- Money as numbers with "qualifier" from the enum; never "$1,000,000 per accident" as a string.
- Translate coverage symbols into "appliesTo" group ids; keep the symbol in "symbol".
- Give every coverage a plainTitle and a one-sentence plain summary.
- Put anything not found in evidence.missing, never in exclusion.
- Rate every watch item: severity = serious | review | info.
- Do not compute status, totals or "other lines"; the front end does.
- Do not hedge ("usually", "see master policy"). If unknown, put it in evidence.missing.
