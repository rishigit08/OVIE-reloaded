Ovie Insights render kit

Every component on the policy summary screen, with its props, and the adapter that turns any extracted policy into a json-render spec. The screen code never knows the policy type: a new policy brings new data, not new UI.

Owner Rishi Verma, designUpdated 14 Oct 2026Matches components.md v2.2 components

How it works

Four steps, one direction. The extraction is the only thing that changes between policies.

payloadExtraction JSON

The AI extraction in contract ovie-insights/2: policy, sections, items. Same item shape in every section.

toSpec(payload)Adapter

Deterministic code. Picks a component per section type, formats values, computes status and monthly, decides what's upfront.

{ root, elements }json-render spec

A flat element map. The screen tree hangs off root; sheets sit beside it, keyed sheet/….

Renderer + catalogScreen

json-render maps each type to an Ovie component. The host implements four actions.

No model at render timeThe adapter is plain code, so the same payload always renders the same screen. The catalog still constrains a model if you ever let one compose layouts.
Sheets live in the specEach bottom sheet is an element that isn't a child of root. openSheet renders elements[sheet] in a native sheet; a second tap inside pushes.
Props are display-readyMoney, dates, missing values and counts arrive formatted. Components only lay out strings, so web and SwiftUI render identically.

Rules

These keep the screen policy-agnostic. A change that breaks one of them needs a design review.

  1. Branch only on section.type, value.type, severity, status, effect and whether a field is present. Never on policy line, label, item id, title or a specific kind or concept value.
  2. Unknown section types render with the standard list (ItemRow). Unknown item fields become KeyValueRows in the item's sheet. Unknown icon keys fall back to a generic icon or a dot.
  3. A row is complete on its own. Never move a limit, status, severity or missing flag into a sheet. Only rows whose sheet has more get onPress and a chevron.
  4. Any item drawn as a card row shows its summary there, in full. A sheet shows only what the card didn't: no repeated value, first scope chip, summary or severity.
  5. Lists stop at the cap (coverage 6, watch 5, exclusions 5, conditions 4, gaps 4, others 5) and end with SeeAll. Sheets with more than 8 items get SheetSearch.
  6. Missing data is amber and never shown as ✕ or under "not covered".
  7. Every sheet ends with PageRefs (when sourced) and SheetActions.
  8. Only Figtree, the seven type steps, and the colour roles in components.md §7. Chips and pills carry no colour except status and severity.
